# Offline Step 1 vector workflow (not a production acceptance report)

This checkout keeps the historical N0 commands and schema-2 manifest unchanged. The new commands operate on schema-3 `lab-oszicar-sphere-v1` records only. Use a selected Python >=3.11 environment: install with `python -m pip install -e "path/to/pipeline v3"`, then invoke `python -B -m dmi_pipeline` or its installed `dmi` command from any directory. Interpreter and input/output paths are supplied for the host; there is no Windows runtime path requirement. The [Perlmutter pilot sequence](PERLMUTTER_F0_PILOT.md) covers explicit material, recipe, launch, executable and readback settings. No pipeline command submits VASP jobs or modifies the source POSCAR. Supply and verify remaining electronic settings, parent restart policy and VASP provenance yourself. Never paste an `INCAR.step1` fragment over existing production settings without review.

1. Prepare an explicit JSON recipe and supply its matching VASP 5/6 direct-coordinate POSCAR: `step1-prepare --recipe recipe.json --poscar POSCAR --output plus-targets`. Required recipe fields: `id`, `family` (`F0`, `F1`, `F2a`, `F2b`), `side` (`+` or `-`), `q_frac` (unwrapped positive wavevector, reciprocal fractional), `axis` (`x`, `y`, `z`), `magnetic_indices` (two distinct zero-based POSCAR ion indices), `signs` (explicit ±1 for those sites), `seed_magnitudes` (positive per magnetic site), `rwigs` (positive, one per species in POSCAR order), `lambda` (explicit zero for readback or positive constraint), `lzeroz` (boolean). F1/F2 also require `angle_deg`; F1 additionally requires `f1_policy: "diagnostic"` because its LZEROZ production choice is unknown. For F0 use `lzeroz: true`, F2 uses `false`. Zero nonmagnetic MAGMOM seeds and zero constraint targets are emitted; acceptance of zero-target exclusion still needs matching production source/binary evidence. A negative-side recipe is reflected from the **unwrapped positive** recipe's vectors, not regenerated using a reduced negative q. To use a wrapped negative representation, first prepare the negative side, then run `step1-wrap-partner --config minus-targets/config.json --q-frac 0.75 0 0 --output wrapped-minus-targets` (for positive q=0.25, negative q=-0.25). This changes only the model q and QSPIRAL; it preserves the reflected physical targets, MAGMOM, M_CONSTR and site order. A wrapped negative recipe field `partner_q_frac` is rejected; do not prepare with a reduced positive q and expect the same physical targets. The measurement axis does not alter SCF tags or targets. F1 signed continuation and F2 near-target cold-start policies still require deliberate parent selection; the tool does not schedule or select parents.
   To assemble a run directory, replace `--poscar POSCAR` with `--inputs shared-material/`, containing nonempty POSCAR, INCAR, KPOINTS and POTCAR: `step1-prepare --recipe recipe.json --inputs shared-material --job-template path/to/working-job.sh --output pilot`. The existing generator supplies config, INCAR.step1 and the magnetic tags in the merged INCAR; those tags override inherited values in the base INCAR. Other base settings, including explicit ENINI, are preserved. Material files and the explicitly supplied launch script are copied unchanged. There is no current-directory job.sh discovery. Omitting `--job-template` writes inputs with an explicit review-only message and ignores any current-directory script; exit 0 means writing succeeded, not readiness to launch. An explicitly requested missing script or missing/empty material file fails before writing. Nonempty destinations are rejected. Restart files/parents and electronic settings remain caller choices. The supplied working script owns executable configuration and launch resources; preparation neither rewrites nor executes it. Keep POTCAR and run directories outside Git. The [local Fe preparation](../evidence/2026-10-19-fe-f0-preparation/README.md) is a generator test; generate the actual pilot on Perlmutter using the [cluster sequence](PERLMUTTER_F0_PILOT.md).
2. Run the VASP parent externally, preserving the exact POSCAR and required input tags in its actual INCAR. Then `step1-read --config plus-targets/config.json --run path/to/run --references references.json --output plus-state.json`. Reference JSON has `M_int` and `MW_int` arrays of same-definition sphere magnitude references, in magnetic-ion order, under the same RWIGS. The checker requires exactly three finite QSPIRAL components in stored q, requested tags, run INCAR and OUTCAR echo before comparing them; it also compares physical targets to run inputs. It requires a single completed OUTCAR run and consecutive indexed OSZICAR electronic/ionic records whose last IDs agree with OUTCAR's final EDIFF loop. OUTCAR `Iteration I(E)` uses ionic I first, electronic E second; `Iteration 1(50)` denotes ionic step 1, electronic step 50. An OUTCAR timing footer, an unindexed OSZICAR excerpt, a truncated terminal block or stale EDIFF is insufficient; incomplete or ambiguous association fails closed. Excerpts alone are never converged runs. Optional `--common-z` permits one shared z rotation for *geometry validation only*, never absolute constraint alignment or fitted vectors. The output retains all ions' two sphere definitions, printed penalty/field and decimal precision, norms, input/config/run file hashes and gate failures. `penalty_check` retains the `MW_int`/penalty interval and the physical penalty threshold. `field_check.status` tests signed factor-two evidence against `MW_int`, using the requested coefficient matched to INCAR and OUTCAR echo; effective coefficient still needs source/build evidence. `field_check.identity` separately reports whether field-implied and printed penalty intervals overlap at that coefficient, or their gap if disjoint. Its status remains unavailable as a same-update consistency check until the update association is established; overlap alone is not a PASS, and a gap is retained rather than hidden by coarse lambda printing. The [source audit](sessions/2026-09-30_1933Z-agent-step1-field-penalty-source-audit.md) found a cached penalty and later moment refresh in supplied code, without authenticating the sample executable or exempting other CGA runs. At zero/under-resolved transverse signal, a consistent zero field may pass the state while factor-two evidence is **unavailable**; `field_check.consistency` records agreement with `MW_int` at printed precision. Missing printed field never establishes a factor-two PASS. A passing geometry gate is not production-build acceptance.
   The input check compares LNONCOLLINEAR, LSORBIT, LSPIRAL and LZEROZ by boolean meaning using the shared strict INCAR logical parser. Thus a prepared `T/F` config can read a historical `True/False` INCAR; invalid tokens and opposite values still fail. The [historical Fe follow-up](sessions/2026-10-19_1556Z-agent-step1-logical-readback.md) reached the physical gate with the unmodified prepared config and retained the prior failure reasons.
3. Independently supply an explicitly canonical, symmetry-vetted bond basis JSON: `{"bonds": [{"a": 0, "b": 1, "R": [0, 0, 0], "p": [[0, 0, 0.001]]}]}`. Endpoint indices are zero-based POSCAR ion indices; `R` is integer cell translation, and each `p` vector gives the coefficient in eV of one shared parameter. Each undirected bond occurs once; changing bond direction requires the corresponding sign change in its propagated axial basis. This file is **not** a BFO fixture or verified symmetry propagation. Call the same vector kernel directly for planning: `step1.coefficients(record["targets"], record["q_frac"], axis, bonds, record["magnetic_indices"])`.
4. Supply an independently obtained `traces.json` with `axis`, `plus_eV`, `minus_eV`, `source` and optional independently measured `sigma_y_eV_per_site`. Then `step1-row --plus plus-state.json --minus minus-state.json --basis bonds.json --traces traces.json --output row.json`. Both sides must pass their own realization checks and have matching per-species RWIGS radii; separately passing states with different integration spheres cannot be paired. The row command rechecks the bound input/config/run hashes, reparses the sphere moments and recalculates each gate with its stored references; editing a passing gate/spin list or changing run files after readback cannot silently yield a row. When both states permit `--common-z`, one signed common rotation is used for the *pair validation only*, not in the two-sided kernel. A single common rotation cannot hide relative-site errors or wrong axial polarity. The output is **diagnostic**, retaining the raw trace pair sum: it is not a passing P0 gate, nor does a numeric uncertainty imply a verified noise model. Full SOC operator x/y rotation still requires genuine T3 evidence; do not rotate SCF targets or PAW projections. If genuinely validated Patch B traces are available, the existing indexed readers and first-order trace remain authoritative; never substitute a total-energy difference or constraint penalty for those traces.
5. `step1-fit --rows rows.json --output fit.json` takes `{"rows": [row, ...]}` and refuses absent uncertainty or rank deficiency. It returns a **numerical diagnostic only**, even with supplied uncertainties. This CLI does not certify covariance, symmetry provenance, P0, T3, BFO rank, or VASP physics; production acceptance remains blocked until independently validated BFO bond basis/9-parameter fixture, converged paired Patch B evidence, replica noise/covariance, axis dumps and production identity are supplied and checked. Do not label its coefficients accepted DMI vectors.

Migration: leave old N0 and angle/OUTCAR-derived records unchanged. The Step 1 commands reject records lacking schema 3 and the exact convention marker; previously saved Step 1 states without full file-bound readback/precision evidence also require re-reading original matched POSCAR, INCAR, OUTCAR and OSZICAR. If these files, consecutive iteration IDs or independent convergence are missing, rerun the relevant parent rather than importing OUTCAR projected moments. A same-ID OSZICAR/OUTCAR match and local hashes are checks against accidental mismatch, **not** tamper-proof provenance against deliberate reconstruction of files/records. They cannot authenticate an executable, establish whether a parent was restarted without visible markers, certify BFO physics, or prove the identity of separately supplied trace/basis/reference files. No production VASP validation was performed by these local tests.

The archived constraint-probe table in `docs/archive/constraint_probe_v2_protocol.md` is historical and its “unwound” production labels are superseded. For a future corrected production probe use **physical lab-frame M_CONSTR and MAGMOM** for F0/F1/F2, fixed SAXIS, separate M_int geometry and MW_int absolute alignment, explicit mode-1 LAMBDA/RWIGS, signed partners and the retained F1 LZEROZ comparison. A deliberately wrong-frame target may be used only as a labelled discriminator, never as a production target. The archived parent/ladder/CP5–CP9 controls are not automatically validated by these local tests.
