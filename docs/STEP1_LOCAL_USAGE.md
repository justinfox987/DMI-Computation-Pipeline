# Offline Step 1 vector workflow (not a production acceptance report)

This checkout keeps the historical N0 commands and schema-2 manifest unchanged. The new commands operate on schema-3 `lab-oszicar-sphere-v1` records only. Run from `pipeline v3` with `C:\Users\finny\miniconda3\envs\research\python.exe -B -m dmi_pipeline`. No command submits VASP jobs or modifies the input POSCAR. These commands create local JSON evidence and an `INCAR.step1` fragment; supply and verify the remaining electronic settings, parent restart policy and VASP provenance yourself. Never paste an `INCAR.step1` fragment over existing production settings without review.

1. Prepare an explicit JSON recipe and supply its matching VASP 5/6 direct-coordinate POSCAR: `step1-prepare --recipe recipe.json --poscar POSCAR --output plus-targets`. Required recipe fields: `id`, `family` (`F0`, `F1`, `F2a`, `F2b`), `side` (`+` or `-`), `q_frac` (unwrapped positive wavevector, reciprocal fractional), `axis` (`x`, `y`, `z`), `magnetic_indices` (two distinct zero-based POSCAR ion indices), `signs` (explicit ±1 for those sites), `seed_magnitudes` (positive per magnetic site), `rwigs` (positive, one per species in POSCAR order), `lambda` (explicit zero for readback or positive constraint), `lzeroz` (boolean). F1/F2 also require `angle_deg`; F1 additionally requires `f1_policy: "diagnostic"` because its LZEROZ production choice is unknown. For F0 use `lzeroz: true`, F2 uses `false`. Zero nonmagnetic MAGMOM seeds and zero constraint targets are emitted; acceptance of zero-target exclusion still needs matching production source/binary evidence. A negative-side recipe is reflected from the **unwrapped positive** recipe's vectors, not regenerated using a reduced negative q. The measurement axis does not alter SCF tags or targets. F1 signed continuation and F2 near-target cold-start policies still require deliberate parent selection; the tool does not schedule or select parents.
2. Run the VASP parent externally, preserving the exact POSCAR and required input tags in its actual INCAR. Then `step1-read --config plus-targets/config.json --run path/to/run --references references.json --output plus-state.json`. Reference JSON has `M_int` and `MW_int` arrays of same-definition sphere magnitude references, in magnetic-ion order, under the same RWIGS. The checker rejects absent/ambiguous OUTCAR completion/EDIFF, mismatched INCAR/POSCAR, and missing or incomplete OSZICAR final records. Excerpts alone are never converged runs. Optional `--common-z` permits one shared z rotation for *geometry validation only*, never absolute constraint alignment or fitted vectors. The output retains all ions' two sphere definitions, printed penalty/field, norms, provenance and gate failures. Printed field factor checks are diagnostic when rounding makes a numeric comparison unreliable.
3. Independently supply an explicitly canonical, symmetry-vetted bond basis JSON: `{"bonds": [{"a": 0, "b": 1, "R": [0, 0, 0], "p": [[0, 0, 0.001]]}]}`. Endpoint indices are zero-based POSCAR ion indices; `R` is integer cell translation, and each `p` vector gives the coefficient in eV of one shared parameter. Each undirected bond occurs once; changing bond direction requires the corresponding sign change in its propagated axial basis. This file is **not** a BFO fixture or verified symmetry propagation. Call the same vector kernel directly for planning: `step1.coefficients(record["targets"], record["q_frac"], axis, bonds, record["magnetic_indices"])`.
4. Supply an independently obtained `traces.json` with `axis`, `plus_eV`, `minus_eV`, `source` and optional independently measured `sigma_y_eV_per_site`. Then `step1-row --plus plus-state.json --minus minus-state.json --basis bonds.json --traces traces.json --output row.json`. Both sides must pass their own realization checks. The output is **diagnostic**, retaining the raw trace pair sum: it is not a passing P0 gate, nor does a numeric uncertainty imply a verified noise model. Full SOC operator x/y rotation still requires genuine T3 evidence; do not rotate SCF targets or PAW projections. If genuinely validated Patch B traces are available, the existing indexed readers and first-order trace remain authoritative; never substitute a total-energy difference or constraint penalty for those traces.
5. `step1-fit --rows rows.json --output fit.json` takes `{"rows": [row, ...]}` and refuses absent uncertainty or rank deficiency. It returns a **numerical diagnostic only**, even with supplied uncertainties. This CLI does not certify covariance, symmetry provenance, P0, T3, BFO rank, or VASP physics; production acceptance remains blocked until independently validated BFO bond basis/9-parameter fixture, converged paired Patch B evidence, replica noise/covariance, axis dumps and production identity are supplied and checked. Do not label its coefficients accepted DMI vectors.
